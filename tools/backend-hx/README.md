# backend-hx — skunkworks bindings backend

**Transient. Intended to promote upstream to `flight-compiler` as `compiler-backend-hx`.**
Hosted here only while its shape is iterated; keep it promotable.

## Job

A pure function: **flight-compiler analysis → Haxe binding source strings**. It emits the
`flight.*` public surface + the hidden `flight._cpp.*` / `flight._js.*` / `flight._hx.*` backings
described in [`../../AGENTS.md`](../../AGENTS.md):

- **Types** → conditional-typedef unifiers (`flight.<Type>` selecting the backend), structural where
  the backend is structural.
- **Function facades** → module-level free functions whose `inline` bodies `#if`-dispatch to the
  hidden backend extern classes.
- **Hidden backends** → `extern class`es carrying `@:native`/`@:include` (cpp) or `@:jsRequire` (js)
  bindings; the `_hx` backing is generated by flight-compiler's implementation backend (or omitted).

## Constraints that keep it promotable

- **One-way boundary.** Import flight-compiler's *public* surface only (never deep internals). Depend
  on nothing in this repo's runtime/build. Runtime/build consume the *output*, never this code.
- **Depend on the stable half.** Consume the API/type **inventory** (signatures, type shapes,
  provenance, target symbol names) — not the volatile statement/expression lowering. Externs have no
  bodies, so the body lowering isn't needed here.
- **Names come from flight-compiler.** Derive C++ symbol names (and JS export names) from
  flight-compiler's own naming — the same that produced flight-cpp — so bindings can't drift from the
  real symbols.
- **House style.** Flat source, functions + plain data (no classes), contracts from
  `flight-compiler`'s `compiler-types`, tests co-located. Promotion should be a `git mv`, not a
  rewrite.

Until this exists, `src/flight/*` holds a hand-written proof-of-shape and `generated/` is empty.
